# Standalone keyboard distribution implementation plan

Status: implemented for v0.1.0 test candidates. Direction approved in chat: independently installable swipe typing for KDE Plasma on Arch/CachyOS and Fedora KDE; no ASUS or touch-profile dependency. The owner approved isolated VM acceptance and subsequently public repository/release publication; the daily installed keyboard remains untouched.

**Goal:** native packages and reversible per-user activation, tested without touching the running desktop.

**Architecture:** packages own runtime code/models under /usr/share/swipe-keyboard and executable entry points under /usr/bin. A per-user controller checks compatibility, installs a minimal stock-English layout hook in a dedicated data tree, and records/restores only its KWin InputMethod change. The launcher regenerates layouts on upstream updates and sets private import/data paths. Recording remains opt-in and data stays in the user's writable folder. No theme, panel, gestures or tablet policy changes.

**Constraints:** x86_64; KDE Wayland; Plasma Keyboard 6.7/6.8 candidate series (current Arch has 6.8; actual stock layout differs only by one added accent; other series fail closed until tested). Native Qt/KF dependency versions are generated by packaging. English swipe recognition only; other stock layouts retained unchanged. No default optional neural/ngram downloads, training data or native build on end-user machines. No -march=native in distributable builds. Container tests do not prove interactive compositor behavior.

## Task 1 — reversible standalone integration

Files: new `integration/swipe-keyboard`, `integration/setup.py`, `integration/layout.py`, `integration/swipe-keyboard.desktop`; new `tests/integration/test_setup.py`, `tests/integration/test_layout.py`; modify model path lookup in `plugin/swiperecorder.cpp` and `plugin/swipeinputmethod.cpp` as needed with a pinning test.

- Write tests using temporary HOME/XDG directories and fake KConfig commands; test unsupported session/version refusal before changes, untouched external layout trees, retained stock keys and symbols, English-only hook, idempotent activation, preserved previous InputMethod, conditional deactivation, and refusal to overwrite a later user change.
- Run `python3 -m unittest discover -s tests/integration -v`; observe missing implementation failures.
- Implement a standard-library-only controller. `check` prints compatibility; `enable` snapshots InputMethod, builds owned overlays and selects the packaged desktop entry; `disable` restores only if still owner; `launch` builds current stock overlays, imports the packaged plugin and execs plasma-keyboard. No process kills or root operations.
- Run the tests and an offscreen layout load against installed Qt, with a private session environment. Never invoke live KWin or the real keyboard process.

## Task 2 — native packaging and reproducible build inputs

Files: CMake install rules; `packaging/arch/PKGBUILD`, `packaging/fedora/swipe-keyboard.spec`, `scripts/package-check.py`, `.github/workflows/packages.yml`, packaging tests; asset fetching/build scripts.

- Write failing tests for staging contents, distro dependency declarations, mandatory model/dictionary/license payload, runtime executable paths and no automatic KWin modification in package transactions.
- Add CMake install rules and distro-native recipes that build on the target distro with CPU-independent defaults. Package optional models separately from the base payload; do not fetch them by default. Include GPL source and third-party notices in release preparation.
- Pin and verify fetched required model assets. Separate build-time dictionary generation from end-user installation.
- Build/test in available isolated environments; record every actual command and any unavailable distro verification. CI builds must not automatically publish releases or assert hardware acceptance.

## Task 3 — release instructions and review

Files: README, CONTRIBUTING, issue template, packaging verification documentation.

- Explain the install/enable/disable/update flows and distinction between package validation and real KDE acceptance.
- Verify `python3 -m unittest discover -s tests/integration -v`, packaging tests, CMake build/ctest, staged runtime plugin load, no unresolved shared-library dependencies, and `git diff --check`.
- Request fresh review; fix findings within scope; rerun relevant checks. Leave changes uncommitted and unpublished unless requested.

## Acceptance evidence

A release needs clean distro package builds plus a real KDE Wayland check of activation, tapping/swiping/candidates, symbols and locale switching, reboot, package upgrade, and disable/removal restoring the user's previous keyboard. Unsupported distro/version combinations must not be advertised as tested. No plan promises zero application-specific text-input limitations.
