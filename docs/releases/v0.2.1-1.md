# Swipe Keyboard v0.2.1-1

Corrective **test release** for KDE Plasma Wayland. English (US/UK), Spanish, French and German swipe recognition runs locally; recording is off by default.

[Downloads](https://github.com/itsdestin/swipe-keyboard/releases/tag/v0.2.1-1) · [Install and enable](../../README.md#install) · [Recovery and privacy](../install-details.md)

These are required release targets, not an optional list of whatever happened to build. `release-manifest.json` records exact source revision, package versions, architectures, sizes and hashes; `SHA256SUMS` checks the final downloads. Complete corresponding source, the source RPM and Flatpak build inputs are developer downloads, not installers.

## Corrections

- Native activation preserves existing attached-keyboard and tablet/desktop visibility policies by default. An always-available visibility policy is a separate, confirmed opt-in; setup does not rewrite an external tablet manager's baseline.
- Keyboard launch preserves intermediate touch positions instead of letting Qt Quick reduce gestures to rendered-frame samples. This corrects demonstrated gesture-shape loss during slow rendering, with the setting limited to the keyboard process.
- Native configuration checks accept valid empty nested KWin tiling groups while retaining raw/inherited, immutable and unsafe-entry safeguards. This fixes the activation refusal found in v0.2.0; it does not rewrite user settings to work around the issue.
- Fresh source archives apply the already pinned runtime/build patches even when extracted beneath another Git checkout. Regression tests exercise the copied command-line entry point and packaging tests after production patching, not only pristine fixtures.
- Arch/CachyOS is included in the required package set rather than omitted from the release.
- ARM64 Plasma Mobile is required independently of x86 Mobile coverage, including architecture-specific build/load and real-input acceptance.

## Release safeguards

The repeatable process is documented in [Releasing Swipe Keyboard](../releasing.md): automatic PR/main builds, a required complete-platform result, matching source/version/architecture evidence, final-byte checksums, and protected approval before publication. Tag builds stay behind that approval so acceptance can identify the actual tag-run package hashes. Earlier source tests or an older package cannot substitute for a new binary's acceptance.

Container/SDK checks establish package, dependency, model, QML/resource and loader contracts. They do not by themselves establish real compositor input, physical hardware compatibility or human language accuracy. ARM acceptance must use the ARM64 package and an ARM64 Plasma Mobile session; a booted ARM OS or x86 session is not enough.

## Installation essentials

- **Deck:** Desktop Mode only. Install the Flatpak per-user, select Swipe Keyboard in KDE Virtual Keyboard settings, and use the bundled settings command in the guide to enable languages. No SteamOS root unlock or system-library replacement. Restore the previous keyboard selection before uninstalling. **Gaming Mode is unsupported.**
- **Native:** install the package matching both distribution and CPU. Run `swipe-keyboard check` and `swipe-keyboard enable` as the logged-in KDE user, without sudo. Do not force dependencies. Disable before removal; preserve legacy restoration records rather than guessing their missing provenance.
- **ARM64 Mobile:** the supplied native package is for Fedora 44/glibc. It is not an Android/iOS app, ARM32 package or postmarketOS/Alpine APK. Other phone distributions and physical-phone performance need separate checks.
- Updates are manual downloads; there is no dedicated AUR/COPR repository or automatic keyboard-update feed.

## Retained limitations

- Contextual next-word suggestions are **English-only** and require the backend's privacy-policy bridge. The bundled Deck backend includes it; stock native backends without it keep predictions disabled. Other languages never use English prediction as fallback.
- Language accuracy is still developing. French **cœur** works with the `coeur` digraph gesture, but the tested shorter `cour` gesture misses; use tapping or corrections where needed.
- Application support depends on Wayland text input and reliable field/cursor/selection information. XWayland and universal browser/Flatpak-client compatibility are not promised. Firefox physical Ctrl+A/Delete can leave an extra leading space.
- Sensitive-field cancellation depends on the application/backend supplying correct input information; no universal privacy guarantee or instantaneous visible-cancellation claim is made.
