# Swipe Keyboard v0.4.0-1

**Test release** for KDE Plasma Wayland and, new, a **preview** of Steam Deck Gaming Mode. English (US/UK), Spanish, French and German swipe recognition runs locally; recording is off by default.

[Downloads](https://github.com/itsdestin/swipe-keyboard/releases/tag/v0.4.0-1) · [Install and enable](../../README.md#install) · [Recovery and privacy](../install-details.md)

## New in 0.4.0

- **Steam Deck Gaming Mode (preview).** Swipe typing and a row of word suggestions on top of Steam's own on-screen keyboard, in Steam and over games. One SteamOS download with `install.sh`; it is opt-in (pressing Enter keeps the Desktop Mode keyboard only) and `uninstall.sh` removes everything it added. **Tested only on a virtual Steam Deck so far, not yet on a real one.** It relies on a Valve developer switch that Steam's rules arguably forbid using this way; read the warning in the [README](../steam-deck.md) first. Steam's password boxes are left alone, and nothing typed over games is learned or saved.
- **Move the cursor with the Space bar.** Slide sideways along Space: slowly for one character at a time, quickly to jump further, like a touchpad. A normal tap still types a space. Works with touch and mouse, in every language layout and in password fields.
- **No more pause when leaving the `?123` page.** Switching between the symbols and letters pages used to reload the swipe dictionary each time; it now stays loaded.

## Gaming Mode preview: what is and is not checked

- Checked in a SteamOS virtual machine running real Steam Gaming Mode: install and uninstall, both install questions, swipe and suggestion insertion into Steam text fields, password-box inertness, the "developer switch turned off" notice, and Steam's own keyboard keeping working when the add-on pauses.
- Not yet checked: a physical Steam Deck (touch feel, speed, battery), and long-term behaviour across Steam updates.
- Known: in the virtual Deck, Steam's own text-typing call sometimes typed the wrong characters, even with this add-on uninstalled (for example `abcd` came out as `ab345`). Whether real hardware does this is unknown; if your swiped words come out jumbled, please report it. If Steam changes something the add-on depends on, it switches itself off and Steam's normal keyboard is used.
- Updates are manual downloads.

## Release safeguards

The repeatable process is documented in [Releasing Swipe Keyboard](../releasing.md): automatic PR/main builds, a required complete-platform result, matching source/version/architecture evidence, final-byte checksums, and protected approval before publication. Tag builds stay behind that approval so acceptance can identify the actual tag-run package hashes. Earlier source tests or an older package cannot substitute for a new binary's acceptance.

Container/SDK checks establish package, dependency, model, QML/resource and loader contracts. They do not by themselves establish real compositor input, physical hardware compatibility or human language accuracy. ARM acceptance must use the ARM64 package and an ARM64 Plasma Mobile session; a booted ARM OS or x86 session is not enough.

## Installation essentials

- **Deck:** Desktop Mode only. Install the Flatpak per-user, select Swipe Keyboard in KDE Virtual Keyboard settings, and use the bundled settings command in the guide to enable languages. No SteamOS root unlock or system-library replacement. Restore the previous keyboard selection before uninstalling. For Gaming Mode, use the separate SteamOS download instead (see the Gaming Mode preview section above).
- **Native:** install the package matching both distribution and CPU. Run `swipe-keyboard check` and `swipe-keyboard enable` as the logged-in KDE user, without sudo. Do not force dependencies. Disable before removal; preserve legacy restoration records rather than guessing their missing provenance.
- **ARM64 Mobile:** the supplied native package is for Fedora 44/glibc. It is not an Android/iOS app, ARM32 package or postmarketOS/Alpine APK. Other phone distributions and physical-phone performance need separate checks.
- Updates are manual downloads; there is no dedicated AUR/COPR repository or automatic keyboard-update feed.

## Retained limitations

- Spanish, French and German next-word suggestions are early statistical baselines and may be repetitive or unnatural. English retains its existing FUTO neural context model. Native mode feeds the model only bounded, confirmed keyboard-owned history; it still reads bounded editor context for validation. Stock native backends hide some application completion preferences, so this is not a claim that every raw application completion opt-out or name/terminal purpose can be honored. Public sensitive/restricted-field checks remain required. The bundled Deck backend retains its raw-policy bridge and stricter application vetoes; any present bridge denial or invalid bridge never falls through to native history. Other languages never use English prediction as fallback.
- Current-word suggestions are dictionary-ranked, not context-aware neural completions. Automatic correction on Space is not included. Next-word suggestions remain available after Space.
- Language accuracy is still developing. French **cœur** works with the `coeur` digraph gesture, but the tested shorter `cour` gesture misses; use tapping or corrections where needed.
- Application support depends on Wayland text input and reliable field/cursor/selection information. XWayland and universal browser/Flatpak-client compatibility are not promised. Firefox physical Ctrl+A/Delete can leave an extra leading space.
- Sensitive-field cancellation depends on the application/backend supplying correct input information; no universal privacy guarantee or instantaneous visible-cancellation claim is made.
