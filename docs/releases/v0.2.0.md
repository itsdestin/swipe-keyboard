# Swipe Keyboard v0.2.0

Swipe typing for KDE Plasma Wayland, now with English (US/UK), Spanish, French and German profiles, English next-word suggestions with the bundled backend, and a per-user Steam Deck Desktop Mode package. **Test release.** Recognition runs locally; recording is off by default.

## Download and install

[Download files](https://github.com/itsdestin/swipe-keyboard/releases/tag/v0.2.0) · [Step-by-step installation](../../README.md#install) · [Setup and recovery](../install-details.md)

| System | File |
|---|---|
| Steam Deck **Desktop Mode**, x86_64 | `org.itsdestin.SwipeKeyboard.flatpak` |
| Fedora 44 KDE / Plasma Mobile, **x86_64** | `swipe-keyboard-0.2.0-1.fc44.x86_64.rpm` |

Download one matching package, not a source archive or `.src.rpm`. `SHA256SUMS.txt` supplies optional checksums. Use the complete corresponding-source archive for rebuilding; GitHub's automatic source downloads omit submodules.

### Steam Deck essentials

- Switch to **Desktop Mode**. Install the Flatpak as your normal user; no SteamOS root unlock or system-library replacement.
- Choose Swipe Keyboard in **System Settings → Virtual Keyboard**. Note the previous selection first.
- **Gaming Mode is not supported.** This does not replace Steam's built-in Gaming Mode keyboard.
- Restore the previous selection in Settings **before uninstalling**. The Flatpak does not automatically restore it.
- Download a new bundle for keyboard updates. A local bundle is not an automatic update feed.

### Mobile essentials

- This means **KDE Plasma Mobile**, not Android/iOS.
- The supplied native package is **Fedora 44 x86_64** with Plasma Keyboard 6.7.x/6.8.x and compatible Qt libraries—not Maliit.
- **No ARM-phone package or physical-phone certification.** Do not install an x86_64 RPM on an ARM device.
- Run `swipe-keyboard check` and `swipe-keyboard enable` inside the logged-in KDE session without sudo. Run `swipe-keyboard disable` before native package removal.

## Changes

- Normal language selection for US/UK English, Spanish, French and German, while respecting the physical keyboard layout.
- Verified language-pack loading; missing/incompatible data keeps stock tapping instead of substituting English swipe recognition.
- Better French elision handling and German noun-case/ß display spelling.
- English contextual next-word suggestions with the bundled privacy-capable backend. Corrections replace a word; next-word choices insert a new one after confirmation.
- Sensitive-field gesture cancellation, including a field that becomes sensitive during a held gesture.
- Safer configuration restoration and clearer install/update/removal instructions.

## Limits users should know

- **Next-word suggestions are English-only.** Stock native backends without the required privacy bridge keep them disabled; the Deck bundle includes the bridge.
- Language accuracy is still developing. French `cœur` works with the `coeur` digraph gesture, but the tested shorter `cour`-shaped gesture still misses. Tapping and correction remain available.
- Application support depends on Wayland text input. XWayland support and universal browser/Flatpak compatibility are not promised.
- Cursor movement, selections or missing field information can prevent corrections/whole-word Backspace. This avoids editing the wrong text.
- Firefox physical Ctrl+A/Delete can leave stale field information and cause an extra leading space.
- No Gaming Mode, ARM-phone, Android or iOS support claim. Virtual-machine checks do not measure physical-device performance or human language accuracy.

## Verification

Build and source checks:

- Fresh combined SDK Qt 6.10.3 build: **35/35 tests passed**; actual patched Plasma Keyboard 6.7.5 backend built and installed.
- Fresh independent installed-input-panel fixture: **21/21 passed in SDK and Platform**; current embedded QML matches the selected source.
- Installed package checks: **43 ELF checks passed**, model/dictionary/license checks passed, Platform native-loading preflight passed.
- Host source checks: combined fixtures **25/25**, packaging **56**, integration **72**, session **6**, language-pack **7**, offline CLI **6** passed. Focused ASan/UBSan checks **3/3** passed; dependency libraries are not claimed sanitized.
- The unchanged 30-case **synthetic** language benchmark improved from 16 to 20 first-choice exact matches and from 20 to 24 top-three matches, with no previously passing case lost. This is not a human accuracy rating.

Installed-system checks, using owned x86_64 virtual machines:

- **SteamOS Desktop:** the combined production keyboard passed swiping, correction, tapping, Backspace, English Space-confirmation/prediction insertion, and normal language-picker journeys for Spanish, French and German. Spanish `hola` and French AZERTY `salut` were recognized; German `hallo` appeared as an alternative to `halo`. These examples demonstrate functionality, not a general accuracy score.
- **Sensitive fields:** password focused before contact, normal-to-password focus change while held, and same-field purpose change while held passed. Held trails canceled without recognition output; ordinary password tapping remained available. No claim of instantaneous visible cancellation is made.
- **Actual SteamOS update:** **3.8.14 / 20260707.10 → 3.8.28 / 20260922.1** through the supported updater. The same per-user app and keyboard selection survived; real input, English predictions and password safeguards were checked afterward. Root protection stayed enabled throughout.
- **Fedora 44 Plasma Mobile, Qt 6.11.2:** the native RPM passed enable, real touch swipe input, disable and exact prior-setting restoration. This is a minimum x86_64 Mobile check, not ARM-phone or rotation/hardware certification.
- Both systems were restored after testing. Final download exports differ from the device-tested payloads only in desktop/provenance metadata; compiled code, QML, runtime scripts, assets and permissions were compared unchanged.

Physical Steam Deck hardware, ARM phones, Gaming Mode, every browser/Flatpak client and native-speaker language accuracy remain unverified. No such coverage is implied by these results.
